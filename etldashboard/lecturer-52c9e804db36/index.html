Describe a process: lecturer manual

This exercise trains describing a technical process in English. Pairs work on two laptops. One student (the hand) watches short station videos and describes them. The other (the voice) listens, takes notes and writes. There are no instructions to relay: the task is watch, describe, write. This process is an ETL process for a sales dashboard: every night the scheduler starts the connectors, which read the new records from the ERP system, the CRM system and the CSV files and copy them to the staging area (extract); the ETL engine cleans the data, removes duplicates and converts it to one format (transform); the data quality check rejects records with errors; the engine loads the clean data into the data warehouse (load); selected data is copied to the data mart, which summarizes it by region and month; and the dashboard asks the data mart for the numbers and shows them as charts.

Before class

  1. Part 1 is an online drag-and-drop exercise: nothing needs to be printed. Students check their own answers on screen.
  2. Open the writing app, start a session and create the writing exercise for the day. The class code appears when you create the exercise.
  3. Decide the pairs. Each pair needs two laptops.
  4. Keep the lecturer vocabulary sheet at hand. It has the answers and sample wording for what each part does.
  5. Test the three links on one laptop, including joining your own session in the writing area.

The links

The site is public, so students do not need an account. Give out one link at a time, when that part starts.

  • Part 1: vocabulary sheet
  • Part 2: watch and describe
  • Part 3: write and check

The Part 2 link asks students to choose a role: "I watch and describe" (the videos) or "I listen and write" (the writing area, no videos).

Running the parts

Part 1: vocabulary

  • Students work alone or in pairs. They drag each name from the word box to the right number: a correct name snaps into place, a wrong one jumps back. The station pictures below the table show the steps in more detail.
  • Check the table together. Have students say each name aloud. Accept other sensible wording for the functions.

Part 2: blind run

  • Make sure the voice does not see the hand's screen (seat them back to back or at an angle).
  • Each station plays once. The page remembers which stations a student has watched, so a reload does not give a second viewing. This is an honor system, not a lock.
  • Use the button "Reset stations" at the bottom of the hand's page if a student needs to start again.
  • Listen in on a few pairs. Notice whether they use the Part 1 names and connectors.

Part 3: write and check

  • Both students open the Part 3 link and join the writing area with the class code and a nickname.
  • Pairs write one complete description. They replay stations on the right of the screen to check it.
  • You can follow all groups in the teacher view of the writing app.

Part 4: feedback

  • Use the group swap in the writing app so that groups read and comment on each other's work.

Language focus

  • Describing sequence: first, then, after that, finally.
  • Process verbs and passive voice: is read, is copied, is cleaned, is converted, is joined, is tested, is rejected, is loaded, is summarized, is shown. Also relative clauses: the staging area, which is a temporary storage.
  • Technical vocabulary for the 11 parts and their functions.

Good to know

  • Check the three links and typing between two laptops before the first class.
  • Students use nicknames. The writing app runs on Vercel and Firebase, so tell students not to enter personal details.
  • Colors in the clips: raw data in different shapes and colors (ERP blue cubes, CRM green cylinders, CSV yellow cones), clean data one standard shape in white, error records red, signals cyan. The data mart shows three regions (teal, orange, violet) and the dashboard bars use the same colors.
  • Simplifications: a night of processing is shown in about 70 seconds; data records are shown as blocks (12 raw blocks, of which 3 duplicates are removed and 2 are rejected by the quality check); blocks fly on conveyors and lifts; the error log from the text is shown as an error bin; the ETL engine appears in two stations (transforming and loading).
  • Students often confuse the staging area (part 6, temporary raw data) with the data warehouse (part 9, long-term clean data), the data warehouse (part 9) with the data mart (part 10, one subject, summarized), and the ETL engine (part 7, cleans and loads) with the data quality check (part 8, tests and rejects). The ETL engine appears in stations 3 and 5.
  • The stations: 1 the data sources, 2 extracting, 3 transforming, 4 quality check, 5 loading, 6 summarizing, 7 reporting.
  • The technical content is simplified for B2 learners and has not been checked by a subject lecturer. Ask a colleague from data engineering or business informatics to look at it before the first class.
